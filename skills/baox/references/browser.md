# 浏览器

## 正常使用

普通 ERP 页面和本地交互页面通过系统默认 Chromium 浏览器打开。系统默认设置不会被 baox 修改，普通的身份读取、项目核验和用户交互仍沿用用户自己的 Chrome 或 Edge。

当材料已确认、流程即将执行 ERP 写入或恢复时，内核还需要一个可接管的 Chromium 页面。如果当前默认浏览器没有可用的自动化连接，`baox next` 会返回一个内核生成的启动步骤；原样执行该步骤后，内核会启动使用独立 baox profile 的 Chrome/Edge Chromium 并打开 ERP。用户只需在这个新窗口登录一次，后续身份探测、恢复回读、发票导入和草稿写入都复用同一个页面。

打开页面不等于能读取 ERP。当前登录身份与项目核验仍由内核只读适配完成。内核报告权限或浏览器能力缺失时，原样说明具体缺项，让用户处理后重试；不沿用旧登录记录，不把用户口述身份记为当前 ERP 探测结果。

完成条件：本地页面已在默认浏览器打开；需要 ERP 读取的步骤得到当前身份下的实际结果。用户完成本地交互后以服务器接受的结果继续；专用自动化窗口在当前任务结束前不要关闭。

## ERP 草稿写入与恢复

确认后的 `erp-write`、写入后的 `erp-reconcile` 和本地恢复快照沿用同一个已选中的、可接管的 Chromium ERP 页面。Chrome 与 Edge 共用 CDP 自动化连接器，不为不同浏览器品牌维护不同业务适配器；连接不到当前页面时在写入前硬阻塞，不切换到 ego，也不猜测其他标签页。恢复回读只读，不会再次导入、填写或保存。

正式模式需要当前 Chrome/Edge 页面可通过 Chromium CDP 连接。`BAOX_CHROMIUM_CDP_PORT` 可指定连接端口，未指定时使用 `BAOX_CDP_PORT` 或 `9333`；这只是连接参数，不是浏览器品牌适配器。

## 自动化 QA

只有当前任务明确选择 ego 自动化 QA 时，才在执行环境设置 `BAOX_BROWSER=ego`，并提供已确认的 `BAOX_EGO_TASK_SPACE`。单独存在 task space 配置不改变正式浏览器选择。QA 执行时保持同一任务空间，按 ego-browser 的控制权协议操作。

完成条件：明确选择的 QA 适配可用，结果标记为 Agent QA；不把 QA 工具要求写成普通用户的安装前提。
