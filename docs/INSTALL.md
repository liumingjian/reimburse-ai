# baox 安装与试用

baox 是一套跑在 Claude Code 里的报销助手：你把发票丢给它，它整理材料、核对、填进 ERP 的费用报销单。
**它不替你提交，也不替你确认**——每一个有后果的动作都要你亲手点。

这份文档是给试用的同事看的。整套东西零依赖、不联网、不上传任何材料。

## 你需要先有

| | |
|---|---|
| macOS | 目前只在 macOS 上验证过 |
| Node.js **21 或更高** | `node -v` 看一下。没有就 `brew install node`，或去 https://nodejs.org 下 LTS 安装包 |
| Google Chrome | 会另开一个**专用实例**，和你日常那个 Chrome 互不干扰 |
| ERP 账号 | 用你本人的账号，登录这件事自始至终在你手里 |
| Claude Code | 已登录可用 |

## 安装

解压拿到的压缩包，里面有三个目录。Claude Code 认两个位置，**试用期请装进项目目录**：

```bash
cd <你打算用来报销的目录>          # 例如 ~/projects/baoxiao
mkdir -p .claude/skills
cp -R baox baox-recover baox-setup .claude/skills/
```

拷完重开一个 Claude Code 会话（在同一个目录里启动）。

### 三条规矩

**一、三个必须一起拷。** 它们共用同一份内核，只拷其中一个会在第一条命令上被拦下来
（`version_drift`）。这是故意的——版本对不上时宁可停住，也不能让新说明书去驱动旧内核。

**二、三个必须在同一个位置，而且来自同一次打包。** 个人目录 `~/.claude/skills/` 和项目目录
`<项目>/.claude/skills/` 都是合法安装位置，但**不要各放一部分**。

**三、个人目录会静默遮蔽项目目录。** Claude Code 的优先级是「个人 > 项目」，同名 Skill 只有
优先级高的那一个会被加载，**另一个既不会报错也不会出现在 `/skills` 里**，Skill 自己也无从察觉
自己被遮蔽了。所以如果你以前在 `~/.claude/skills/` 下装过 baox，现在又往项目目录里放了一份新的，
跑的仍然是旧的那一份。装之前先看一眼：

```bash
ls -d ~/.claude/skills/baox*        # 有东西就说明存在遮蔽风险
```

有的话，把个人目录里那套删掉（或挪走）再装项目目录这套。也可以在 Claude Code 里跑
`/skill-doctor`（v2.1.252 以上），它会直接告诉你每个 Skill 实际是从哪个目录加载的。

> 这不是假想的：第一次真机试用栽的就是它——个人目录里一份半年前的 `baox-setup` 遮蔽了项目目录里
> 的新版，用它的旧内核覆盖了数据目录，结果登录了也永远显示"未登录"，而且哪一层都不会报版本不一致。

等整套框架稳定之后，我们会改成推荐装在个人目录（一次安装，所有项目可用）。现在还在试用期，
装项目目录更容易看清楚跑的到底是哪一份。

## 第一次使用

在 Claude Code 里说一句：

> 帮我把 baox 环境装一下

它会走完体检 → 安装内核 → 起专用 Chrome → 核对身份 → 试一次选择界面。中间有两步要你动手：
**在新开的那个 Chrome 窗口里登录 ERP**，以及**在弹出的网页上点一次提交**。
两步都完成了才算装好。

## 日常使用

> 帮我报销 ~/Downloads/8月出差

它会盘点材料、认发票、问你拿不准的地方，一路走到把单子填进 ERP。
**最后的保存和提交仍然是你自己按。**

三个 Skill 的分工：

- **baox** —— 正常的报销流程，从材料到填单
- **baox-recover** —— 一张单子已经往 ERP 写过东西之后的对账收尾（发票可能已被占用，只读排查）
- **baox-setup** —— 环境准备，以及后面每次更新版本时重装内核

平时你只需要开口说要干什么，它自己会挑。

## 你的数据在哪

全部在你自己的机器上，`~/Library/Application Support/baox/`：

- `runtime/` —— 内核本体
- `chrome-profile/` —— 专用 Chrome 的独立 profile（调试端口只绑 `127.0.0.1`，不碰你日常的 profile）
- 任务工作区 —— **发票副本和识别结果**

也就是说这里面是真的发票。要清理直接删这个目录；删掉之后重跑一次环境准备即可。
账号密码只经过你自己的手，任何时候都不写进这些文件。

## 更新到新版本

1. 把新的三个目录整份覆盖进**原来那个位置**（三个一起）
2. 在 Claude Code 里说「帮我重装一下 baox 内核」

第 2 步漏了的话，下一条命令会被 `version_drift` 拦住并告诉你怎么做——不会带着错位的版本继续跑。

反过来，如果重装内核时被 `downgrade_refused` 拦住，说明数据目录里装着的内核**比你正在跑的这个
Skill 还新**——几乎总是因为机器上有两套 baox，跑的不是你以为的那一份。先按上面「三条规矩」查一遍
安装位置。确实要退回旧版时，说「用 `--allow-downgrade` 重装 baox 内核」。

## 报问题

请附上这一句的输出，里面有版本号：

> 帮我跑一下 baox 体检

没有版本号的问题定位不到具体是哪一版，基本查不动。再加上你当时说了什么、它做了什么、
你期望它做什么，就够了。

## 目前的边界

- 只在 macOS + Google Chrome 上验证过（Windows 有代码路径，没实测）
- 只对着一套 ERP 验证过
- 提交和最终保存永远是人来做，这是设计，不是待办
