# ERP WebAPI 写入限制的独立复核

状态：2026-10-30，历史与官方文档复核完成，现场只读复核受登录入口阻塞；当前账套的写接口权限和业务等价性尚未实测。本轮没有调用 `Save`、`Draft`、`Delete`，测试凭据仅用于登录，没有输出。

## 结论

“正式 WebAPI 集成需要管理员配置第三方授权”有官方依据。
“本项目已经实测证明 WebAPI 写明细不可用”没有在本轮检索范围内找到依据。
当前证据既不能证明能直接切换为 API 写入，也不能把它判定为技术上不可行。
维持页面填写路径，并把 API 写入作为独立验证方向。

## 历史记录证明了什么

[验证台账 V-60](erp-expense-flow/verification-ledger.md) 记录 2026-09-20 的实测：

- 已登录页面通过 cookie 调用 `ExecuteBillQuery`、`QueryBusinessInfo`、`View` 成功。
- 元数据中存在费用报销单的 `Draft`、`Save`、`Delete` 等操作；整张单及费用明细模型可读取。
- `Draft`、`Save`、`Delete` 当时一次都没有调用。操作存在不等于当前账号有调用权限。

[ADR-0033](../adr/0033-headless-executor-with-hosted-erp-credentials.md) 因写入签名未验证而延期 API 写入，没有给出真实权限拒绝的结果。
[probe-webapi.ts](../../server/scripts/probe-webapi.ts) 明确仅发送三个只读服务。
Git 历史中 `c864c86` 和 `9be1a86` 对应上述调查与设计，未发现写接口被管理员权限拒绝的测试记录。
本轮 `gh issue list --state all --search 'WebAPI'` 返回空列表；这只描述当前检索结果，不证明所有历史讨论都不存在。

## 官方依据与适用边界

### 第三方授权和登录

[金蝶云星空二次开发规范](https://open.kingdee.com/k3cloud/open/DevelopStandard.html) 要求 API 开发使用第三方系统登录授权，并由系统管理员确认。

[官方 SDK 配置说明](https://open.kingdee.com/K3Cloud/Open/ApiCenterReportDetail.aspx) 指示管理员在系统管理中创建第三方授权，再配置账套 ID、集成用户、应用 ID 和应用密钥。
这确认了所有者记忆中的管理员配置成本。配置授权与使用 Administrator 作为日常业务调用身份是不同事项。

### 操作权限和接口可达性

[BOS 平台参数配置产品手册](https://help.open.kingdee.com/dokuwiki/doku.php?id=bos%E5%B9%B3%E5%8F%B0%E5%8F%82%E6%95%B0%E9%85%8D%E7%BD%AE) 列出独立的限制：WebAPI 总开关、操作与字段权限控制、查询数据权限、允许调用用户，以及 IP、客户端和接口白名单。
当前账套是否启用这些配置，本轮没有读取，不能由公开文档推定。
即使同一会话可以查询，保存也可能因具体接口或操作权限而被拒绝。

### 会话复用不等于写入授权

仓库中 cookie 读取成功是已验证的技术事实。
[官方接口说明书](https://vip.kingdee.com/article/490771221039228672?productLineId=1) 也描述登录后复用会话，而非每次请求重新登录。
但公开资料没有证明本项目复用网页会话进行写入满足目标账套的授权配置，也没有证明该会话可调用费用报销单写操作。
不应以共享 cookie 作为绕过正式第三方授权要求的方案。

### 字段模型和保存业务逻辑

[WebAPI 保存接口说明](https://vip.kingdee.com/article/112644692445323776/) 将 `formid` 与 `data` 分开，数据包还涉及更新字段、分录删除策略、子系统以及基础资料校验等选项。
读出的实体字段键不自动构成合法的保存输入契约。
费用项目、项目、税额、收票绑定和本账套自定义字段仍需逐项验证，不能以一个成功 HTTP 状态或一个成功返回替代保存后核对。

## 尚需独立验证的内容

本轮在当前 macOS 上执行了两个现场检查：

- 现有 `probe-webapi.ts` 无法连接 `127.0.0.1:9333`，当时没有调试浏览器监听。
- 使用项目现有浏览器启动和登录实现，新建临时无头浏览器并加载本机测试凭据。
  登录返回 `erp_sign_in_no_form`，未进入元数据请求。另以 GET 和 HEAD 检查同一 ERP 登录入口，均返回 HTTP 403。
  临时浏览器已关闭，未创建报销单。登出请求也未取得 HTTP 响应，不能宣称已成功登录再登出。

HTTP 403 出现在登录入口，不是费用报销单 WebAPI 写权限的拒绝证据。
因此这次现场结果只证明当前访问条件下无法继续，不能将管理员授权要求改写成已验证的当前账号写入失败。

1. 在目标账套只读核对其实际版本、WebAPI 开关、允许用户/接口以及费用报销单操作授权。无权读取时如实记录，不改管理员配置。
2. 确认是否已有正式第三方授权与可用的集成身份。无需把密钥写入研究文档。
3. 使用明确限定的测试身份和材料，进行一次费用报销单暂存写入，核对返回错误类别及完整模型。真实写入实验需要单独定义目标单据和残留处理，不调用删除或提交。
4. 对照当前页面路径检查项目、费用项目、票种、日期、城市、金额、收票和多段分摊。所有字段及业务后置条件一致后，才评估替换成本与性能收益。

缺少第 3、4 项时，结论只能是“正式接入有管理员配置依赖，目标账套的写入能力未证实”。
