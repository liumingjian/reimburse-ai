## 已验证流程

1. 在“我的费用报销”列表点击“新增”，系统在新的页签打开“费用报销单-新增”。
2. 新增单包含“基本信息”“付款信息”“明细信息”“收票信息”四个区域；页面实际上同时保留各区域 DOM，页签用于定位区域。
3. 新增时自动生成一条明细行，并带出当前日期、当前部门、当前申请人、人民币、普通发票等默认值。
4. 在“收票信息”点击“选择发票”会打开第三方“发票无忧助手”。助手支持发票影像、附件影像、企业收到的发票和移动端票夹四类采集入口。
5. 助手中的发票在选中后汇总张数、附件数、价税合计和税额；“发票导入单据”是回写 ERP 的明确边界。本次未点击该按钮。
6. ERP 顶部的“保存”和“提交”是两个独立动作。即使没有人工填写字段，默认值和弹窗操作也会令新增页进入“内容已经修改”状态。

## 表单字段

以下默认值均以当前登录用户的新增单为准。涉及姓名、工号、电话和组织编码的具体值未写入证据。

## 发票无忧助手

现场和已有截图共同确认以下入口：

### 上传发票影像

- “上传发票”文件选择器
- “手工录入”
- 官方 Excel 模板下载链接
- 电子发票提示要求上传 PDF 或 OFD 原文件；当天开具的发票可能暂时无法查验，提示次日再上传

手工录入弹窗包含发票代码、发票号码、开票日期、校验码后六位，并提供“发票查验”和“清空”。页面明确提示：手工录入采集的发票没有发票原图，建议上传影像。空字段点击“发票查验”后没有捕获到明确的字段级错误文本，因此不能据此断言具体必填校验行为。

### 上传附件影像

- “上传附件”文件选择器
- “开始扫描”
- 该分支将材料计入附件数，不等同于已识别发票数

### 企业收到的发票

查询条件包括销方名称、发票代码、起止发票号码、开票日期范围和发票使用状态。结果表包含发票摘要、价税合计、税额、开票日期和发票信息，并支持分页。

### 移动端票夹

查询条件包括报销状态和开票日期范围；现场默认状态为“未用”。结果表包含发票摘要、价税合计、税额、开票日期、发票信息和操作，并支持分页。

所有分支共用“继续采集”和“发票导入单据”按钮，以及已选发票/附件和金额汇总。

## 技术观察

- 当前 ERP 登录页和金蝶动态表单服务均使用明文 HTTP。后续 Agent 不应在不可信网络运行；正式方案应优先推动 HTTPS，或至少限定在受控网络/VPN 和隔离执行环境中。
- ERP 是金蝶动态表单应用，页面元素 ID 和 Playwright ref 含运行时 UUID，不能作为长期稳定定位器。
- 应优先使用表单标识 `ER_ExpReimbursement`、可见标签、页签名称、工具栏命令和表格列名定位，并在每次动作后验证当前页签和表单状态。
- ERP 业务调用主要经过金蝶 `DynamicFormService.Call` / `CallByUrl` 一类服务；本次只观察请求名称，没有保存请求体、Cookie 或会话参数。
- 发票助手是 `piaozone.com` 的跨域嵌入页面，使用短期、用户绑定的 URL 参数和接口。实现时不得固化或持久化这些参数，应从已授权浏览器会话进入。
- 发票助手加载了一个失败的分析脚本请求，但主要页面和查询接口正常返回；该 404 目前不影响流程判断。
- 点击“控制检测”后系统明确提示当前用户没有查看权限。Agent 不应依赖该菜单完成提交前校验，应把权限限制暴露给用户。

## 自动化边界

建议把后续 Agent 分成五个可审计阶段：

1. 本地整理发票、账单和用户补充信息，生成结构化候选数据。
2. 在上传前展示文件、金额、税额、费用项目、项目、承担部门和事由的映射建议。
3. 经授权后进入 ERP 新增页，填写表头和明细，再导入发票。
4. 核对 ERP 回写的票据状态、金额汇总和明细金额，任何不一致都停止自动化。
5. 在“保存”或“提交”之前展示最终差异供用户确认；保存草稿是否允许自动执行，需要单独决策。

不能将以下内容自动推断后静默提交：费用项目、项目、费用承担部门、申请付款/退款模式、收款对象、异常发票处理、预算/审批绕过。

## 尚未验证

以下事项需要真实样票或明确的状态变更授权，当前不能视为“完整端到端流程”已走通：

- 上传 `refenrences/fp-jd.pdf` 后的识别、查验、重复票检测和错误处理
- `refenrences/zd-jd.pdf` 作为附件上传后的关联方式
- 发票导入单据后，票面字段如何映射到明细行及金额字段
- 多张发票对应一条/多条费用明细的规则
- 项目、费用项目、承担部门选择器的实际候选值与预算联动
- 保存、提交时的完整必填校验、预算校验和审批路由
- 多收款人、申请退款、外部承担、机票报销等条件分支
- Excel 模板的实际列结构和批量导入行为

仓库中的两个候选样本均为单页、未加密 PDF：`fp-jd.pdf` 是电子增值税专用发票，`zd-jd.pdf` 是账单。本次未将它们发送到 ERP 或第三方发票服务。
