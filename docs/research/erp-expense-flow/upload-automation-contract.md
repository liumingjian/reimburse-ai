# 发票自动上传契约

> **实现注记（2026-09-11）：** 下文按 Playwright `filechooser` 描述；实际实现是内核 CDP 链路（`kernel/src/invoice-upload.mjs`）。固定 ERP 入口与无人值守上传的结论不变。

验证日期：2026-09-04

## 结论

用户不需要在每张发票上参与文件选择。一次性完成浏览器会话授权后，baox 可以从任务材料盘点生成的“纯发票上传目录”自动调用文件选择器，把每个主要报销凭证交给 ERP 关联的发票助手；用户仍只在任务授权、异常处置和最终保存权限边界上参与。

当前仓库没有证据证明发票助手存在可供本项目使用的官方上传 API。因此 v1 应采用“受控浏览器自动化 + 可替换 API 适配层”的结构：先把 Playwright 文件选择器流程做成可审计的外部动作，后续拿到厂商正式 API、幂等键和状态查询契约后再替换上传适配器。不能把页面私有接口或短期 URL 参数固化成生产 API。

## 固定 ERP 入口

v1 内置且唯一的 ERP 入口是 `http://erp.antute.com.cn/k3cloud/html5/index.aspx`。初始化引导、报销任务和本地 Web 都不要求用户输入 ERP 地址，也不提供任务级自由替换；入口是产品配置，不是个人绑定或报销事实。

当前入口使用 HTTP。它可以用于用户打开页面并进行人工探索，但这不等于满足正式自动化的安全前置条件。自动填入凭据、上传、导入和保存之前，必须确认实际会话使用 HTTPS 或经批准的等价安全通道；如果唯一入口长期只能使用明文 HTTP，自动化发布必须保持阻塞并明确转人工边界。

## v1 流程

1. 本地整理阶段扫描材料，固定每个文件的路径、哈希、材料角色、票种、发票身份和预期金额。行程单、水单和其他参考材料只进入证据关联，不进入上传目录。
2. 前置检查阶段按发票身份检查当前任务内重复、外部记录未知、字段缺失、金额不守恒和角色冲突。存在任一阻塞性的 `待确认项` 时，不打开任务选择 Web，也不启动 ERP 上传。
3. 用户授权后，从当前已授权 ERP 会话进入“不生成费用明细 -> 电脑端选取”的关联入口。短期用户参数只在当前会话内使用，不写入配置、日志或任务事实。
4. 对任务整理工作区中的上传清单逐张执行 Playwright 文件选择器：等待 `filechooser` 事件，点击实际“上传发票”控件，再以绝对路径设置单个 PDF、PNG 或 JPG 文件。文件选择器由 Agent 完成，用户不需要逐张操作。
5. 每次识别后读取候选数量、发票身份、开票日期、金额、税额和票种。候选缺失、字段不一致、参考材料进入发票队列或出现重复提示时，立即停止并形成 `ERP 动作尝试` 与 `待确认项`。
6. 只有候选与本地材料唯一匹配、金额守恒且没有重复事实时，才允许点击“发票导入单据”。导入后立即只读核对收票行数、明细行数、金额字段和关联状态；不能把按钮点击成功当作回写成功。
7. 明细字段按已确认的 ERP 字段契约填写。保存是唯一允许的最高写入动作；保存后必须同时看到单据编号生成和页签进入“修改”状态，才能记录 `ERP 草稿` 已保存。提交、审核、下推、付款和解绑永远不在 v1 自动执行。

## 动作账本

上传不能只记“文件已经选中”。每个 `ERP 动作尝试` 至少记录以下脱敏事实：

- 任务和 `ERP 就绪快照` 版本；材料哈希和材料角色
- 上传意图、关联入口、派发时间和候选识别状态
- 识别到的发票身份摘要、金额、税额、票种和匹配结论
- 导入派发结果、ERP 收票/明细回读结果和金额守恒结果
- 重复、权限、会话超时、页面不一致或任何未知结果
- 保存派发结果、单据编号/页签状态后置条件和最终控制权

会话失效、写入结果未知或页面关联上下文丢失时，必须先做 ERP 对账或转人工，不能重放上传、导入或保存。

## 生产前置条件

- 厂商确认的上传、识别状态查询、重复查询、导入和保存接口，或稳定的浏览器自动化入口
- 可查询且可隔离的发票外部记录；无法查询时默认阻塞，不假设不存在重复
- 专用测试租户，或能够重置收票助手和未保存草稿的测试流程
- ERP 表单、发票助手和浏览器会话均使用 HTTPS 或经批准的等价安全通道；当前固定 HTTP 入口在该条件确认前只能用于人工探索；短期 URL、Cookie 和 token 不进入持久化事实
- 每种发票场景都有验收样本和金额/身份/行数断言，尤其是多段网约车、负数行、铁路客票和住宿专票

本次现场验证证明了 Playwright 文件选择器可以在用户授权后无人工逐张参与地完成 PDF 上传；非重复的曹操主发票已在重新授权的 ERP 关联上下文中自动上传并成功关联导入，随后按常住城市广州和交通项目 `111454` 完成明细映射并保存为 ERP 草稿，证明用户不需要逐张选择文件。但导入后自动生成的明细仍出现费用金额/税额语义不一致、默认发票类型和缺失业务字段，因此自动上传必须与前置重复门禁、导入后对账和保存后置条件绑定，不能独立做成“批量上传按钮”。个人账号只能验证当前账号的机械流程和外部状态，不能替代可隔离的测试租户或厂商接口契约。

## 2026-09-04 PNG 上传补充

`交通/fengyun-1.png` 在新的 ERP 关联上下文中完成了单文件上传、助手识别、`发票导入单据`、ERP 收票回读和保存草稿；对应的 `交通/行程单.png` 没有进入发票队列。识别结果为 1 条数电票，收票回读不含税 `18.25`、税额 `0.55`、价税合计 `18.80`，没有出现重复提示。导入后明细仍先把价税合计写入费用金额并留下空税额，说明 PNG 文件格式不会改变“上传成功不等于业务明细正确”的后置门禁。

在当前 Chrome 扩展会话中，发票助手位于跨域 iframe，标准 Playwright `filechooser` 事件无法稳定取得；本次验证使用了仅服务于该测试文件的临时本地 CORS 文件服务，再通过浏览器会话内 CDP 的 `DataTransfer` 注入文件对象完成受控上传。该方法仅是当前环境的验证手段，不能作为生产实现或稳定 API。正式实现必须选择厂商确认的上传接口，或经过版本绑定、权限约束、审计和回读验证的受支持浏览器上传适配器；临时 URL、Cookie、token 和文件内容不得进入持久化动作账本。
