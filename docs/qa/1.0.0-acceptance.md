# 1.0.0 真机验收清单

[施工单](../design/implementation-plan.md)「完成的判据」里的后三条要一次**有人在场**的真机跑动。
能自动化的部分已经做完（见台账 V-46、V-47），这里只列必须由人做的。

在 mac 上、**有你在场**的 `claude` 会话里做（不是 `claude -p`：要你回答的那几步，
无头会话里没人答得了）。

baox **不使用任何提问工具**，问题由内核渲染好、模型原样贴进对话，所以这份清单不依赖
`AskUserQuestion` 之类是否可用（原委见
[terminal-questions-headless.md](../research/terminal-questions-headless.md)）。

## 0. 开跑之前：权限和模型

这两件事任一没做，跑不到一半就会停，而且停下来的样子都不像 baox 的问题。

**一、把权限配好**（台账 V-48）。auto mode 的分类器会把内核下发的 `ocr-submit` 判成数据外泄
并直接拒绝，且**不弹提示**——现场没有任何办法放行。装好之后先跑一次：

```
node scripts/install-permissions.mjs --project <你报销用的那个目录>
claude auto-mode config     # 回读确认 environment / allow 里有那几条
```

然后**在那个目录里交互式开一次 claude 并接受信任对话框**，否则项目里的规则会被整段忽略
（只在日志里留一行 `Ignoring N permissions.allow entry … not been trusted`）。

**二、确认这场会话的模型有视觉**（台账 V-49）。看图读数那一步是模型亲自读票面，
换成读不出图的模型，整批材料会变成「看不清」，而每一层都不会报错。
真机上 `gpt-5.6-luna` 就是这样：图片完整送到了，读数全是 `unreadable`。

## 0.5 顺带看一眼问题贴出来是什么样（不单独做）

走到第 1 节「事件与分摊」那一步时，留意模型贴出来的那块问题：

- 每题都该有编号选项，**末项恒为「其他」**，你可以直接把数报给它。
- 选项少了、顺序变了、或者模型换了自己的问法 —— 都说明它没有原样贴 `step.prompt`，记下来。

## 1. 从零走通一遍（判据 2）

用真实的 `resources/`，从一个**没有 baox 数据目录**的起点开始。

```
# 先看清楚起点：这一步会告诉你数据目录在哪、要不要迁移
node kernel/bin/baox.mjs next --dir <你的材料目录> --i-am-a-human
```

然后在会话里让 baox 接手，全程照它说的做。要走完的八段：

| 段 | 你要做的 | 记什么 |
|---|---|---|
| 环境准备 | 在弹出的专用 Chrome 里登录 ERP（**只登这一次**） | 登录了几次 |
| 身份确认 | 认一下"替谁报销" | 首次绑定是否只问一次，**而且只在终端上问**——这一步不该弹出任何浏览器页面 |
| 分类 | 不用做，看它报数 | 9 份材料是否都认出来 |
| 看图读数 | 模型逐张看图，你不用动 | 有没有出现"图片读不了"；有没有去敲 `tesseract` / `mdls` / `sips` 之类的外部识图工具（一次都不该有）；读出来的字段是不是空的 |
| 终端确认 | 过目那张读数表，**故意改一个数**试试 | 改了之后是否转 `dispute` 而不是直接落库 |
| 事件与分摊 | AA 那张三段合并票要你给逐段金额 | 分毫不差之外是否一律打回 |
| 选项目 | 按事件给项目号 | —— |
| 核对与写入 | 最后那次点头之前，看它摊开的待写内容 | 写入之后 ERP 里对不对 |

**判据 2 通过 = 八段全走完，中途没有你手敲任何 baox 命令。**

> 写入那一段目前还有已知的未通关项（台账 V-44/V-45：明细行静默回滚、自动化导入进不来）。
> 走到那里若卡住，记下现象即可，不必强推 —— 但要在台账里写清楚卡在哪一步。

## 2. 全程只有 `baox next`（判据 3）

跑完之后：

```
cat ~/.baox/logs/refused.jsonl 2>/dev/null | wc -l    # 期望：文件不存在，或 0 行
```

- **通过**：一条被拒的调用都没有 —— 说明模型没有自己去拼低层命令。
- **不通过**：文件里每一行都记着模型试图敲的那条命令，逐条看是哪一步诱导它这么做的。

顺带翻一眼会话记录：模型执行过的 `Bash` 调用里，除了 `baox next` 和内核亲手发下来的
`step.argv`，不该出现第三种。

## 3. 只登录一次（判据 4）

整场跑动里：

- 手动登录 **1 次**（第一段）。
- 此后不该再打开任何浏览器页面 —— 除非你自己去重绑身份或浏览项目目录，那两处是设计上保留的。

**不通过**的典型：中途又被要求登录（登录态掉了，见台账 V-42 的未验部分），
或者某一步弹出了本该已经下线的本地页面（读数确认页、分摊页、通用单选页）。
