## 用户逐项验证

- [ ] 首次确认本人身份与常驻城市；新建下一任务时沿用城市，既有任务保留原快照。
- [ ] 盘点能说明纳入与排除的材料；行程单、水单作为参考材料，已报销测试票不会混入本次发票目录。
- [ ] 对照原件核对主发票票种、代码/号码、净额、税额、合计；铁路票面没有的字段明确保留缺失。
- [ ] 行程单逐段日期、起点、终点正确；酒店入住和离店日期来自水单；开票日不代替费用发生日。
- [ ] 多行程发票的各段金额与发票总额精确一致；不能凭总额守恒就忽略方向或日期错误。
- [ ] 识别候选不会逐张打断用户；项目选择和准备工作完成后只出现一次最终整单确认表。
- [ ] 最终表按费用分类排序（本地市内交通、外地市内交通、长途交通、住宿，无组标题、无合计行），共 13 列：发票 | 项目号 | 起始日期 | 结束日期 | 住宿地/城市 | 出发点 | 目的地 | 费用分类 | 费用项目 | 发票类型 | 费用金额 | 税额 | 总额；发票为短标签，项目号与费用项目为「编码 / 名称」，费用金额为不含税金额，不展示完整发票号码或材料关联。
- [ ] 重新识别或改变材料后，旧最终确认失效；确认表能显示当前采用的内容。
- [ ] 本人项目维护支持录入、核验、复检和删除；没有有效项目时明确要求维护。
- [ ] 批量选择可以全选、按类别选择、只看未归属并批量归入本人项目。
- [ ] 已归属明细改派时，覆盖、只处理未归属、取消三条路径结果符合选择。
- [ ] 每条明细有项目、报销事由已填写后才能提交；外部项目号和已删除项目不能用于新的归属。
- [ ] 重开选择页能辨别当前有效选择与已失效选择；长项目名在桌面和窄屏均完整可读。
- [ ] 最终发票目录只含本次主要报销凭证原件副本；文件数量和明细引用一致，一票多行不会重复复制发票。
- [ ] 明细文档能找到每行对应的发票、参考材料、日期、项目编码/名称、费用项目、票种映射及净税合计来源。
- [ ] 机器可读 JSON 与可读明细文档金额、行数和项目一致；缺项清单列明所有尚未充分的内容。
- [ ] 材料包有缺项时不会声称可自动填报；准备确认不会变成 ERP 写入授权。
- [ ] 换票、修改金额或改派项目后，旧材料包不再被当作当前确认版本；重新生成的内容与本次选择一致。
- [ ] 完成后清楚交接目录与文档路径，流程停止；ERP 单据没有因这次 QA 被导入、填写、保存或提交。
