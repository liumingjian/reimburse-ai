# ERP 前准备流程 QA 3

日期：2026-09-10。候选版本：`1.1.0-qa.3`。

## 本轮修复

- Setup 在材料解析前检查并安装锁定的 MarkItDown 与受管本地 OCR；系统默认浏览器和 ego QA transport 使用同一依赖闸。
- PDF 只转换为带行号 Markdown，再从 Markdown 产生封闭 JSON 候选；工单不再携带页图，也不要求模型打开 PDF 或渲染图片。
- PNG/JPG 默认由模型视觉直接读取；显式选择 `ocr-assisted` 时才先走 `extract-reimbursement-images` 本地批处理，证据不足、单图 OCR 失败或候选校验失败时进入模型视觉复核。
- OCR 工单由内核原子落盘；字段候选继续经过内容哈希、闭集字段、日期格式和金额守恒校验，识别结果不逐张打断用户，最后在整单明细表中由用户对照原件统一确认。
- 确认内容与准备包缺项改为标准 Markdown 表格；用户话术只保留状态、表格和下一步。

## 自动验证

- 图片字段提取单测、类型检查与构建通过。
- Setup 依赖、受管 Python、安装态/仓库态路径与 PDF 直接执行测试通过。
- 图片工单、落盘、字段映射、全部行程段保留、确认表和准备包测试通过。
- 完整内核测试和分发包 QA 以本候选最终执行结果为准。

## 人工 QA 边界

本轮不填写 ERP。人工 QA 从真实材料开始，依次核对 PDF Markdown 候选、图片 OCR 候选、分类明细确认、个人项目簿选择、目录只读核验、准备缺项表和最终交接包。OCR 的速度已有 38 张真实图片测试；字段准确率尚未形成逐类型人工金标，不能用 OCR 自己的输出证明准确。
