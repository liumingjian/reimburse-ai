## 当前范围

用户已批准从整单确认直接进入 ERP 草稿自动填报。本轮补齐准备材料包到 ERP 导入、明细填写、单次保存和严格回读的生产接线；提交、审批和付款仍不在范围内。

项目、费用项目和已存在收票证据的只读核验仍属于可用的数据准备方式；是否具备新鲜可靠的证据须明确记录，不能把历史结果当作当前可用事实。

## 第一阶段验收要求

1. 发票专属目录：只放本次有效、待报销的原始发票副本；行程单、水单、排除项及派生 Markdown 不混入待上传集。保留原件，记录文件与材料身份、哈希的对应关系。
2. 填写明细专属文档：包含报销身份与事由、每条费用的发生日期/住宿区间/行程、项目编码与名称、费用项目编码与名称、原生票种及 ERP 类型映射、净额/税额/合计、对应发票与字段来源。建议提供可阅读的 Markdown 和同源 JSON，避免分别维护两套数据。
3. 独立充分性判定：列明缺字段、缺证据、未确认、金额不守恒、项目失效等问题；没有未决项才能声明字段足够自动填报。铁路票面缺失的净额/税额不能反算或补零。
4. 准备阶段终点：生成、校验并确认材料包；确认后由内核发出一次性 `erp-write`，显式选择“不生成费用明细”，上传主要发票，填写完整明细并保存草稿。旧 `ready_for_erp_write` 确认凭据不能生成新的写入。
5. 交接版本：文件、字段、项目或证据改变后，旧包与旧确认失效；检查输出目录不会重新进入输入盘点，搬迁后仍能核验本次交接材料。
6. 填报字段的完整落盘：费用项目编码与名称的核验结果已纳入新的目录记录及准备包；旧目录记录须重新核验。准备包包含原生票种、已核实的 ERP 类型映射及出处；没有可信映射的票种保持阻塞。

当前准备构建器已生成独立的发票目录、参考材料目录、同源 Markdown/JSON 明细及校验清单。文件生成不代表字段充分，字段充分也不代表用户已确认。严格写入预览另有构建器，但依赖收票绑定，不能直接作为尚未导入新票的准备阶段终点。收票号等 ERP 导入后产生的标识属于第二阶段运行结果；第一阶段需要完整发票身份与明确对应规则。

旧版发票使用代码加号码，当前严格写入预览仍只接受 20 位全电身份；准备包应保留原生身份，并如实标明后续写入适配状态。
