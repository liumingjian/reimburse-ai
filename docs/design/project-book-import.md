# 项目簿批量导入

状态：已实现（2026-10-30）。本次访谈的全部规则已获维护者确认。

## 已确认范围

- 项目簿原“项目号”改称“项目序号”，继续用于唯一识别和 ERP 精确匹配。
- 项目簿原“项目名称”改为保存 Excel 的“项目号”列。Excel 的“项目名称”列不导入。
- ERP 核对得到的正式名称另行保存，不覆盖项目簿的项目号。见 [ADR-0042](../adr/0042-project-serial-and-project-number-are-distinct.md)。
- 项目簿、手动新增和编辑、任务项目选择使用一致的字段名称。
- 个人项目簿和公共项目簿都支持批量导入。员工维护自己的个人项目簿，公共项目簿仍由管理员维护。
- 第一版支持 `.xlsx`，按“项目序号”和“项目号”表头定位，允许列顺序变化和其他列存在。
- 文件有多个工作表时，由用户选择工作表。
- 选文件后先展示解析结果和问题行，用户确认后写入。

## Excel 读取规则

- 所选工作表的首个非空行为表头，必须包含唯一的“项目序号”和“项目号”列。
- 去掉表头和字段值首尾空白，保留字段内部字符。
- 项目序号按文本保留，包括前导零。数字单元格保留其格式显示的前导零。
- 两个字段都为空则跳过。仅缺一个字段则标为错误。
- 两列中的公式单元格标为错误，提示先在 Excel 中转为值，避免导入过期计算结果。

## 重复与更新

- 以项目序号判断是否为同一个项目。
- 目标项目簿中两字段相同的项目跳过。项目序号相同、项目号不同的项目展示新旧值，由用户逐项勾选是否更新。
- 更新只修改项目号，保留原截止日期和启用状态。
- 文件内两字段完全相同的行合并。同一项目序号对应不同项目号时，该序号的所有行均标为错误。
- 个人导入遇到公共项目簿占用的序号，跳过并提示可直接使用公共项目。
- 公共导入遇到已有个人项目的序号，提示使用现有转公共项目流程，不自动转换。

## 错误与提交

- 缺少必填字段、同序号内容冲突的行标为错误，预览展示原始行号和原因。
- 允许用户确认仅导入正常行。错误行不参与写入。
- 提交失败时，本次选中的新增和更新全部不写入，不保留部分成功。
- 确认导入时重新检查权限、重复和冲突。若预览后的变化影响本次新增或更新，整批不写入，提示刷新预览后重新确认。

## 状态与已有数据

- 只读取“项目序号”和“项目号”两列，忽略审核状态、禁用状态及其他列。
- 新项目默认启用，不设截止日期。去报销时仍核对 ERP 当前状态，导入不等于通过 ERP 核对。
- 原项目簿的“项目名称”现值保留，改在“项目号”字段展示，之后可通过导入更新。
- 已有任务的确认记录保留原值，不追溯修改。

## 验收条件

| 场景 | 预期结果 |
| --- | --- |
| 向空项目簿导入样表 | 预览 4 条新增；确认前无写入，确认后新增 4 个项目；使用 A 列项目序号和 B 列项目号，不使用 C 列项目名称 |
| 对同一项目簿重复导入样表 | 4 个已有项目跳过，不新增重复项目 |
| Excel 列换序、增加其他列或存在多个工作表 | 由用户选择工作表，按表头取两列 |
| 表头缺失或同名列重复 | 显示结构错误，不允许提交 |
| 项目序号带前导零、值有首尾空白 | 保留前导零，去掉首尾空白，保留内部字符 |
| 空行、单字段缺失或公式单元格 | 空行跳过；问题行显示原始行号和原因，允许确认仅导入正常行 |
| 文件内同序号重复 | 完全相同行合并；不同项目号的冲突行全部标错 |
| 同序号的项目号发生变化 | 展示新旧值，只有用户勾选的项目被更新，截止日期和启用状态保留 |
| 个人与公共项目簿发生占号冲突 | 依照冲突规则跳过或提示转公共项目流程，不自动改变归属 |
| 普通成员尝试向公共项目簿导入 | 拒绝写入 |
| 预览后权限或相关项目变化 | 确认时重新检查；影响本次写入则整批不写入，要求刷新预览 |
| 批量写入失败 | 本次新增和更新全部不写入，重试不会留下上次部分写入的项目 |
| 导入后执行 ERP 核对 | 按项目序号精确匹配，采用独立的 ERP 正式名称执行和回读，不覆盖项目簿项目号 |
| 已有项目簿和历史任务 | 原项目名称保留为项目号；已有任务确认记录不被追溯修改 |

## 验证事实

用户提供的样表包含一个工作表、21 列和 4 条项目记录。第一行为表头，前三列依次为“项目序号”、
“项目号”和“项目名称”。项目序号样例为 `103520`，项目号为包含客户、项目标题、年份和序号的长字符串。
样表的项目序号无重复，两列均无缺值。这些事实不代表其他导出文件也满足相同条件。

## 实现与验证

- Excel 读取规则由 `contract/src/project-xlsx.ts` 实现，个人簿和公共簿共用解析与行分类规则。
- 导入入口位于项目簿页面及项目归属页内的项目簿面板。普通成员没有公共簿导入入口。
- 服务端预览不写项目事实。每个账号在每种项目簿中保留一份待确认预览，有效期为 30 分钟。
- 文件大小上限为 10 MB。服务重启、预览过期或重新生成预览后，需要重新预览再确认。
- 提交在同一个数据库事务内复查权限、占号与所选项目的原状态，再追加全部项目事实。
- 沿用原有 `number` 和 `name` 存储字段，分别表达项目序号和项目号；原数据无需重写。
- ERP 正式名称保存在任务的 `catalog_confirmed` 事件和执行计划中，不再追加覆盖项目簿项目号的事实。
- 自动测试覆盖表头、列换序、前导零、公式、空值、文件内重复、更新、占号、权限、过期、并发和失败回滚。
- 浏览器回归覆盖模拟界面的 Excel 导入，以及已有的手动录入、编辑和项目归属流程。
- `project-import` 验证场景通过真实构建的应用导入维护者提供的 Excel，核对个人簿、公共簿和重复导入后的服务端数据。
  该场景不操作真实 ERP。

再执行 `pnpm exec node .claude/skills/verify/drive.mjs .claude/skills/verify/scenarios/project-import.mjs`。
