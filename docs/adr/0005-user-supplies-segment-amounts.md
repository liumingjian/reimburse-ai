# 合并交通发票的逐段金额由用户给出，系统只做税额切分

> 2026-09-09 实现核对：下文保留原决策及渠道迁移历史。当前 `events.mjs` 已采用更窄的提问条件：用户已给出的有效分摊优先；否则，行程单逐段金额与发票合计按分精确守恒时由内核核对采用，不能守恒时才要求用户逐段给出。此处同步已有行为，MarkItDown 迁移不改变该规则；字段候选仍须经过分类明细确认。见 [ADR-0011](0011-markitdown-agent-pdf-candidates.md)。

一张交通发票对应多段行程时，每段的**价税合计必须由用户在本地分摊页上直接给出**。
系统不平均、不按比例、不按距离、不按时长，也**不自动采用行程单上的逐段金额**。

用户给出逐段价税合计之后，系统才做一件确定性的算术：把每段的价税合计按票面自己的
不含税/价税比切成不含税和税额，并检查三项分别与票面守恒。

## Considered Options

- **自动采用行程单的逐段金额**：实测 AA 样本里行程单的三段金额 26.69 + 20.85 + 21.65
  正好等于票面价税合计 69.19，技术上完全够用。但行程单是**参考材料**，它上面的金额
  不是票面法定金额；设计共识写明"没有逐段金额时，用户必须直接提供每段税价合计"。
  金额相加对得上只说明这份行程单大概率属于这张发票，不说明系统有权替用户认定每段该报多少。
  折中做法：把行程单的逐段行作为**预填候选**摆在分摊页上，并标注来源，由用户核对后提交。
- **按段数平均、按里程或按时长分摊**：明确禁止。这类规则看上去合理，但它们是**发明出来的**
  业务事实，一旦写进 ERP 草稿就变成了报销依据。
- **让用户连每段的不含税和税额一起填**：最保守，但把一件确定的算术推给了人，
  三段就要填九个数字，还会引入人为的凑数误差。
- **不拆，一张发票就报一条明细**：ERP 的费用明细要求日期、城市、起终点，
  三段行程的这些字段各不相同，合成一条就丢掉了真实的费用事实。

## Consequences

- **拆分本身也必须有证据。** 之所以知道 AA 那张票是三段，是因为行程单上逐行列着三段行程
  （`splitBasis: itinerary_rows`）。没有行程单佐证时按一次行程处理，并如实说明依据是
  `no_itinerary` —— 不按金额大小、文件名或票面项目数去猜段数。
- **没有分摊就不产生事件。** 缺逐段金额时这张发票**一个费用事件都不生成**，
  而不是先按总额建一个事件再回头修。`allocation_required` 是硬阻塞，退出码 2。
- **切税额不是分摊费用。** 每段的价税合计已经由用户定死，按票面比例把它切成不含税和税额，
  用的是这张票自己印着的税率，不是推测。分位除不尽时余数落在**价税合计最大的那一段**
  （并列取最靠前的一段），并在输出里如实报出 `residue` —— 这一分不藏。
- **相加差一分都不收。** 逐段价税合计之和必须与票面按分精确相等，页面上实时显示差额，
  内核再校验一次。不提供"接近就行"，也不替用户把差额抹到某一段上。
- **分摊绑定发票的内容哈希。** 发票材料一换，之前提交的分摊立即失效（`allocation_stale`），
  必须重新分摊。这与看图读数的绑定规则一致（[ADR-0004](0004-vision-reads-images.md)）。
- **代价：三段行程要用户填三个数字。** 预填候选把它降成了"核对并提交"，但这一步无法省掉，
  也不应该省掉 —— 它是把"这段行程该报多少"这件事的裁量权留在人手里。

## 补记 2026-09-07：渠道从本地分摊页换成对话提问

这条 ADR 的**判定不变**——逐段价税合计仍然只能由用户直接给出，系统仍然不平均、不按比例、
不按距离时长，也不自动采用行程单上的金额，相加仍然差一分都不收。变的只是**用户在哪儿给**：
本地分摊页（`allocate` 命令 + `serveAllocation`）已经下线，改走 `baox next` 的对话提问
（`step.kind: "ask_user"`）。上面正文里凡是写「本地分摊页」的地方，现在读作「对话提问」。

换渠道的理由不在分摊本身，而在 1.0.0 的那条主线：模型不选命令，只执行内核给的那一件事。
每多一个本地页面，就多一条「用户在别处点过头」的路径，也多一次前台阻塞——而这三个数字
在终端上就问得清楚。本地页面收窄到重新绑定身份和浏览完整项目目录两处。

预填候选这件事跟着一起搬了：行程单上的逐段金额现在是对话提问里的**候选项**，来源照样标注，
末项恒为「其他」可自由输入，还多了一个「这张票我认不出」——整张退回待办，
比报一个凑得平的数字好。收下的门槛一分没让：`submitAllocation` 是同一个函数，
只是 `submittedVia` 从 `local-web` 变成 `terminal`（旧任务里存着的 `local-web` 仍然读得出来）。
