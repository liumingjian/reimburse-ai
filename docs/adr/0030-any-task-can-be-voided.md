# 任何状态的报销任务都可以作废

ADR-0007 立过一条规矩：动过 ERP 的任务（包括写入结果不确定）不允许作废，
它占用的发票只能靠只读对账解除。用意是好的 —— 不知道有没有落进 ERP，就得当成落进去了。
但跑了一年下来，这条规矩真正的效果是**任务退不掉**：

- 对账判成 `不自洽`／`转人工` 之后，只剩 `hand_off` 一条路，对账本身还不许重跑；
- 写入中断、ERP 会话掉了、或者只是想重来一次，任务就永远挂在列表里；
- 「一个账号同时只能有一个进行中的任务」这条约束叠上去，一个退不掉的任务会**把整个应用堵死**，
  用户除了 完全重置 没有别的出路 —— 而 完全重置 同样绕过 ERP 那边的既成事实，
  代价却比作废大得多。

2026-09-20 决定：**任何状态的报销任务都可以作废。**

唯一保留的拒绝是这个任务自己的写入或对账**正在跑**。那不是一个状态，是一瞬间，
它会自己跑完，不需要别的动作来解除；而在浏览器还在往 ERP 里打字的时候把任务抽掉，
留下的是一张没有主人的单据。

## 作废做什么，不做什么

- **做**：把任务标成 `voided`，从列表中移除。事实留在本机（ADR-0015），它占用的发票释放，
  可以在别的任务里使用。
- **不做**：不碰 ERP。已经导入的发票、已经产生或保存的费用报销单，作废之后原样留在那边，
  要员工自己去 ERP 里处理。确认框对动过 ERP 的任务换一段更硬的文案，把这句话说明白
  （`ABANDON_TASK_COPY.dialogBodyErpTouched`）。

## Considered Options

- **维持 ADR-0007，用「对账解除占用」当唯一出口**：这正是现在堵死的那条路。对账自己会走进
  只允许 `hand_off` 的终局，出口在终局之后就没了。一个依赖后续步骤才能退出的状态机，
  只要那一步失败，就没有退出。
- **只放开终局任务（已交接／转人工），写入结果不确定的仍不许作废**：听着稳妥，
  但恰恰是「写入结果不确定」这一类最需要退出 —— 它是失败留下的状态，不是成功留下的。
- **作废但保留发票占用**：占用留着，重复报销的防线就还在。但这样作废就退不出材料，
  同一批发票再也进不了新任务，用户还是被堵住，只是堵的位置换了一个。
  而且重复导入的真正防线在 ERP 那边：同一张发票的 收票占用 由 ERP 自己拦（ADR-0025/0026），
  baox 这份本机占用是提醒，不是唯一防线。
- **加一条「强制作废」的隐藏命令**：两条路径做同一件事，其中一条没人测过。不如只留一条。

## Consequences

- 重复报销的本机防线变弱了一格：作废一个已导入的任务之后，baox 不再拦同一批发票进新任务。
  ERP 侧的 收票占用 仍然拦。这是一次有意的交换：用一格提醒换任务能退出。
- 完全重置 跟着放开 —— 它本来就是批量作废，现在清掉的范围和作废一致。
- `ABANDON_TASK_COPY.blockedReason` 的含义变了：从「动过 ERP，永远不能作废」变成
  「正在跑，等一下」。任务列表里那个禁用按钮现在是瞬态的。
- QA 可以在同一个数据目录里反复跑整条流程，不必每轮换一个 `BAOX_DATA_DIR`。
