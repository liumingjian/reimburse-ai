# 下一步做什么由内核判定，模型只执行；`baox next` 是模型唯一的入口

> **Status: superseded (2026-09-15, #197).** Superseded by ADR-0014: the server derives stage and step from stored facts; `baox next` and the kernel were deleted in #197. Paths below point into git commit `50931a3`, the last one that has the Skill-era code.

> **状态：部分取代（2026-09-11）。** 见[本地报销应用](../design/standalone-app.md)：状态判定是纯函数、`stepToken` 幂等、不许跳步继续有效；消费方由模型换成应用服务端和页面，「`baox next` 是模型唯一入口」「模型原样念 `speak`」不再适用，`speak` 措辞改为页面文案。继任 ADR 待补。

0.9.x 里模型读 SKILL.md，自己决定下一条跑什么、参数怎么拼。那是模型质量差异
**唯一**的入口，真机 QA 的两个 bug 都是从这里进来的：一次是跳过看图直接说"图片读不了"，
一次是命令在前台阻塞时无法把地址转达给用户。两个都不是"模型不够聪明"，
而是"这件事本来就不该由模型决定"。

1.0.0 把决策整体搬进内核：模型只会 `baox next`，拿回一个 `step`，照做，交结果。

三个决定：

- **状态判定是一个纯函数**（`50931a3:kernel/src/state.mjs`），入参是一份采集好的观测对象。
  采集（碰文件系统和 CDP）单独放在 `50931a3:kernel/src/observe.mjs`。分层是硬要求：
  状态机的测试要能在一台没有 Chrome、没有材料目录的机器上跑完。
- **`stepToken` 是"不可跳步"的物理实现**，不是给模型的告诫。凭据跟着状态走：
  状态没变就是同一个凭据（幂等），状态一变旧凭据当场作废。回传的凭据对不上就
  **忽略回传、重发当前步骤**——不报错、不惩罚。
- **`speak` 的措辞写死在内核里**，模型原样念。措辞是模型之间差异最大的地方，
  而这套东西说的每一句话都关系到用户会不会点头。

状态清单与判据见 [state-machine.md](../design/state-machine.md)，
`next` 的输出契约见 [next-contract.md](../design/next-contract.md)。

## Considered Options

- **继续把判断写在 SKILL.md 里，写得更细致些。** 这是 0.9.x 的做法，也是最省事的一条路。
  它失败的方式不是"模型读不懂"，而是**没有任何东西能观测到模型有没有照做**：
  说明书里写"看图之前先 Read"，模型说"我看过了"，内核这一侧看到的完全一样。
  状态推进只认内核自己观测得到的事实，这一条在散文里实现不了。
- **让模型选命令，但用 hook 校验参数。** 校验得了参数，校验不了**顺序**和**跳步**。
  而且校验规则会变成第二份判断逻辑，和 SKILL.md 里那份慢慢对不上。
- **每个状态一条独立命令，模型按状态名去调。** 那还是模型在选，只是选项换了个名字；
  "现在是哪个状态"仍然由模型判断，而这正是要拿走的那个决定。
- **把 `next` 做成一次跑到底的批处理。** 走不通：这条流程里一半的步骤要人动手
  （登录、过目读数、拍板、点保存），另一半要模型动手（看图、问用户）。
  `next` 每次只交出**一件**事，交给谁做写在 `actor` 里。

## Consequences

- 模型这一侧的说明书从"怎么判断"塌成"怎么执行"：七种 `step.kind` 各该做什么，
  以及什么不能做。三份 SKILL.md 各自 ≤120 行，且由测试钉住。
- 低层那二十来条子命令仍然存在，但**只给人手敲排障用**。模型碰不到它们：
  见 [ADR-0010](./0010-kernel-side-command-guard.md)。
- 状态多了一个必须有人维护的清单。判定顺序本身是契约的一部分
  （同时满足多个判据时先报哪个），所以它有自己的测试。
- 内核变"厚"了。这是这套设计的代价，也是它的全部意义：厚在一个确定性的、
  测得动的地方，而不是薄在一个每次运行都可能不一样的地方。
