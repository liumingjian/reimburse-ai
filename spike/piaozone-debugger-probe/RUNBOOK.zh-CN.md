# 排练探针运行手册（#250）

这份手册写给在键盘前的人。扩展是 agent 写的，但只有你能把它跑起来——它要接管你已经登录的报销系统页面，
agent 碰不到那台机器，也碰不到那个账号。

跑完之后，请把「观察结果」整块贴回
`docs/research/spike-250-chrome-debugger-and-datatransfer.md` 的「实际观察」一节。
**看到什么就写什么，没看到的不要补**——那份文档现在写着「未回答」，它就应该只被实测值改写。

## 这次排练会做什么、不会做什么

会做：新开一个报销系统页签（你自己登录）→ 打开一张费用报销单-新增 → 用
「收票信息 → 选择发票 ▾ → 不生成费用明细」打开发票无忧助手 → 试三条路径去触达助手所在的跨域 iframe →
进「电脑端选取」上传页 → 在页面里构造 `DataTransfer` 赋给隐藏的文件控件 → 回读识别出来的行。

不会做：**不点「发票导入单据」**，**不勾选任何识别结果**，**不点保存**，**不删单据**。
按 ADR-0025，消耗发票的是「发票导入单据」那一下，这次排练停在它之前，所以一张发票都不会被消耗，
这套流程可以重复跑。扩展里根本没有点它的代码路径，页面一打开会先跑一遍「防误点自检」，七条全绿才算这句话成立。

排练结束后那张费用报销单是没保存的草稿。**关页签时选「否」（不保存）**即可，不要保存，也不要删除。

## 准备

1. 一台能打开报销系统的 Chrome 或 Edge（Chromium 内核，版本越新越好；`chrome.debugger` 只有 Chromium 有）。
2. 至少一个发票文件。**第一次跑，强烈建议只用这一个**：仓库里的合成样张
   `fixtures/generated/m05-caocao-invoice.pdf`。它的发票号码和销方都是编造的，助手可能接受或拒收；
   以第⑦步的 `assigned` 和第⑧步的上传完成提示/回读确认字节进了文件控件、控件被触发。
   即使识别出合成样张，也绝不勾选或点「发票导入单据」，而且不必把真发票送到第三方 `piaozone.com`。
3. 第一次跑请只选同一种格式（全是 PDF），不要 PDF 和图片混选：助手的上传批次按格式分组，混选会多一个变量。

## 装载扩展

1. 地址栏输入 `chrome://extensions`，回车。
2. 右上角打开「开发者模式」。
3. 点「加载已解压的扩展程序」，选中本目录 `spike/piaozone-debugger-probe`（选目录本身，不是里面的文件）。
4. 装好后在扩展列表里能看到「baox 排练探针 (spike #250)」。把它固定到工具栏，方便点。

如果加载报错，把报错原文抄下来，这本身就是一条观察结果。

## 开跑

点工具栏上的探针图标，会新开一个「baox 排练探针」页签。**所有操作都在这个页签里**，一步一个按钮，
扩展不会自己往下跑。每一步的输出都进下方「运行日志」。

### 第 0 步：看防误点自检

页面最上方的表格应当是七行「通过」。**只要有一行不通过，就停下不要继续**，把那一行抄回来。

### ① 打开报销系统页签

会新开一个报销系统页签并切过去。**在那个页签里正常登录**，登录完切回探针页签。
如果弹「该帐号已登录在线」，按你平时的习惯处理。

### ② 挂上调试器

点完之后 Chrome 顶部会出现一条黄色横幅：「"baox 排练探针" 正在调试此浏览器」。
**这条横幅是正常的，不要点它的「取消」**——点了就等于把调试器拔掉，排练要从第 ② 步重来。
横幅会一直挂着，直到第 ⑨ 步。

这一步还会把页面里的 iframe 结构打一份快照进日志。

### ③ 打开费用报销单-新增

走菜单开一张新的费用报销单。如果你已经手动开好了，这一步会自己跳过。
**表单里什么都不用填**：这次排练不写表头、不写明细。

### ④ 打开发票无忧助手

会点「收票信息」展开区域，再点「选择发票」右边的下拉箭头，然后在弹出的三项里
**只点「不生成费用明细」**。另外两项会让报销系统自己去写费用明细，且不可撤销，所以探针在落点确认到
`tbNotFillEntry` 之前不会点任何东西；确认不到就报错停下。

点完，助手窗口应当弹出来，里面是四个入口（电脑端选取 / 手机端选取 / 扫码枪扫描 / 扫描仪扫描）。
如果弹出「温馨提示」弹窗，不用管，探针后面会自己点「知道了」。

### ⑤ 探针一：能否触达 piaozone iframe

**这是问题①。** 探针会依次试三条路径，而且三条都会试完，不会因为第一条成功就跳过后面的：

- **路径 B**：`Target.setAutoAttach {flatten:true}` + 用 `{tabId, sessionId}` 发命令（服务端执行器现在用的那套）
- **路径 C**：`Target.getTargets` → `Target.attachToTarget {flatten:true}` → 同样用 `{tabId, sessionId}`
- **路径 A**：`chrome.debugger.getTargets()` → `chrome.debugger.attach({targetId})` 直接挂到 iframe 上

日志里每条路径会记下成功或失败，成功的会附上在 iframe 里读到的 `location.href`（应当含 `piaozone.com`）。
**三条全失败也是一个有效结果**，照抄回去就行——那说明 ADR-0021 改成全 `chrome.debugger` 这条路走不通。

### ⑥ 进入「电脑端选取」上传页

探针会等入口页真正就绪，再**静置约 10 秒**才点「电脑端选取」。这 10 秒不是凑数：点早了会触发一次整页跳转，
跳到一个能加载但永远不挂载的空白路由。请耐心等它。

进到上传页后，日志里会有文件控件的现状：`multiple`、`accept`、是否隐藏、当前 `files` 长度、祖先节点、
有没有 React/Vue 的内部属性。这些都要贴回去。

如果日志提示「助手里已经有 N 行识别结果」，说明这次不是干净起步，记一笔，结论要按这个背景读。

### ⑦ 探针二：注入 DataTransfer

**这是问题②。** 先用按钮左边的文件选择框选好发票文件，再点按钮。探针会：

1. 在扩展里把文件读成 base64（这一步模拟的是将来服务器把原件字节发下来）；
2. 在 iframe 里用 `Runtime.evaluate` 把字节还原成 `File`；
3. 构造 `DataTransfer`，`input.files = transfer.files`；
4. 依次派发 `input` 和 `change` 事件；
5. 回报赋值前后的状态。

做完这一步，探针会**立刻进入只读阶段**：此后任何鼠标/键盘事件都会被刹车拒绝，日志里会明确写一行
「探针已进入只读阶段」。

看日志里的 `赋值结果`：`assigned` 是控件真正拿到的文件名和字节数，`assignError` 非空就说明赋值本身被拒了。

### ⑧ 回读识别结果

只读，最多等两分钟。会回报：助手一共几行、本次新增几行、当前是哪个票种分页、每个分页的标题计数、
可见行的发票号码和各列内容、以及助手弹出的任何提示（拒收理由通常在这里）。

**注意：所有行的 `checked` 都应当是 `false`。** 探针不勾选任何行。

### ⑨ 结束：卸载调试器

卸掉调试器，黄色横幅消失。然后：

- 回报销系统页签，**关掉那张没保存的费用报销单，问「是否保存」时选「否」**。
- 不要保存，不要删除任何单据，不要点「申请解绑」。

## 把结果带回来

1. 点「复制观察结果」，粘进
   `docs/research/spike-250-chrome-debugger-and-datatransfer.md` 的「实际观察」一节，
   把那一节的「未回答」字样替换掉。
2. 点「复制完整日志」，附在同一节下面（太长可以只留和两个问题相关的部分，但不要修改内容）。
3. 如果中途在某一步停住了，**停住的那一步也要抄**：报错原文、当时的日志、Chrome 版本。
   一次没跑完的排练，答案就是「未回答」加上它卡在哪里，这比补一个猜测有用。

## 想重跑

排练不消耗发票，可以重跑。重跑请：

- 关掉那张没保存的费用报销单（选「否」）；
- 回到探针页签，**刷新它**（清空状态），从第 ① 步重来。

有一件事我们并不知道、而这次排练正好能顺便回答：**上传但不导入、放弃单据之后再开助手，助手还能不能加载。**
语料里对「导入之后重开助手」的记录是互相矛盾的，而「上传后不导入再重开」从来没人观察过。
如果你重跑了一遍，请把第二遍能不能正常开起来也写进findings。

## 出问题时

- **横幅被点了「取消」**：调试器已断开，日志里会有「调试器已断开」。从第 ② 步重来。
- **第 ④ 步报「没有确认落点」**：菜单没展开或被别的窗口盖住。把报错里的 `items` 和 `hitId` 抄下来，
  这是有用的观察，不要绕过它去手点。
- **第 ⑤ 步三条路径全失败**：这就是问题①的答案。照抄，不要重试到它成功为止。
- **第 ⑥ 步进了空白页**：点早了。刷新探针页签，关掉助手窗口，从第 ④ 步重来。
- **助手拒收合成样张**：可能发生，也不代表问题②失败。看第 ⑦ 步的 `assigned` 和第 ⑧ 步的助手提示/回读；
  如果助手接受并识别出样张，同样只记录证据，不勾选、不点「发票导入单据」。
