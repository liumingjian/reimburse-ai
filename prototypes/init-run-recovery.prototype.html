原型问题

异常发生后，用户从哪里安全地继续？

本原型验证：在不改变既定“报销任务阶段 + ERP 动作尝试”模型的前提下，CLI、本地 Web 和有头 ERP 浏览器分别承载哪些异常；重新进入时复用哪些持久事实，何时允许继续，何时必须停止写入或转人工。

评审假设：这是状态与控制权原型，不是终端或 Web 的视觉定稿。页面内存不会持久化，也不会连接 Codex、凭据库或 ERP。

                CLI

                新任务采用新版本；旧任务按原事实恢复
                不得用新配置静默重解释既有任务或快照
              
      
              
      
                运行中断
                CLI
                任务 ID、阶段、已接纳事实与用户回答
                baox resume TASK_ID 启动新受控运行
                不在后台继续；不重复已接纳问题或复制任务
              
      
              
      
                Web 已打开但任务状态变化
                Web
                服务器任务版本与已提交选择
                冻结旧页，载入当前版本；必要时返回 CLI
                拒绝旧版本提交，清除未提交的界面选择
              
      
              
      
                ERP 自动化暂停
                CLI；Web 只读镜像
                原快照、已验证动作、暂停原因
                固定恢复命令；先只读对账再恢复控制
                暂停时无后台动作；不能从上一个写动作直接续写
              
      
              
      
                ERP 写入结果未知
                聚焦 Web 恢复页；CLI 保持生命周期
                追加式动作尝试、目标身份、预期后置条件
                只读对账、保持暂停、绑定确切结果、确认不存在或转人工
                禁止盲目重放；证据不唯一时不能继续写入
